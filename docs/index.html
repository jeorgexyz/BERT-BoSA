Abstract

This project tests simulated annealing as a way to choose training hyperparameters for a BERT-style text classifier trained from scratch on AG_NEWS. The search changes learning rate, encoder dropout, and encoder depth. Each candidate trains for 300 batches and is ranked by validation cross-entropy loss. In the recorded run, the best candidate reduced this short-run loss from 1.4264 for the starting configuration to 0.9803. After three full training epochs, the selected configuration achieved 87.34% test accuracy, compared with 88.08% for the starting configuration in an earlier run made with a previous version of the search code. This result is consistent with a mismatch between the short search budget and the final training objective: a model that improves quickly may not finish strongest. Because the comparison uses single runs whose random-number state is not matched, it should be treated as a case study rather than a general conclusion about simulated annealing.

How the search works

Each step perturbs one hyperparameter — learning rate (×[0.5, 2], clamped to [1e-5, 1e-3]), encoder dropout (±0.1, clamped to [0, 0.5]), or layer count (±2, clamped to [1, 16]). A fresh model trains for 300 batches under the candidate configuration and is scored by cross-entropy on held-out validation batches. A lower-loss candidate is always accepted; a higher-loss one is accepted with the Boltzmann probability

$$P(\text{accept}) = \exp\left(-\frac{L_{\text{candidate}} - L_{\text{current}}}{T}\right),$$

which is where the Boltzmann in BoSA comes from. Cooling is geometric, with the rate derived from the iteration count so the temperature falls from 0.1 to 0.001 across the run. Early on, the search can move uphill and escape local optima; as $T$ falls it turns greedy.

Why loss, and not accuracy

An earlier version scored candidates by 1 − accuracy. Every one of the 16 candidates scored exactly 0.744375 — chance accuracy for four balanced classes. Within a short budget each model still predicts a single class, so accuracy cannot separate them. Every proposal was then accepted with probability $\exp(0) = 1$ and the search degenerated into a random walk that returned its own starting point. Cross-entropy responds to confidence, so it separates candidates long before accuracy moves off chance. That degenerate trace is kept in the repository as baseline_accuracy_cost_sa_log.csv.

Results

Configuration Learning rate Dropout Layers Val. loss @ 300 batches Val. acc. @ 300 batches
Starting configuration 0.0001000 0.2000 8 1.4264 26.25%
Best by validation loss (iter. 14) 0.0000737 0.1681 5 0.9803 60.44%

Those are candidate-evaluation numbers, not final results. Trained for three full epochs, the selected configuration reached 87.34% test accuracy. The untuned eight-layer starting configuration reached 88.08% in an earlier run.

The search succeeded at its stated task and still lost. It found a configuration with substantially lower loss after 300 batches, and that configuration finished 0.74 points behind the baseline after full training. A five-layer encoder makes faster early progress; a deeper one benefits more from longer training. The search optimised early progress because that is what it was asked to measure.

What this does not show

  • Both final numbers come from single runs with no seed variation. A 0.74-point gap is well within the range seeds alone could produce.
  • The two runs were produced by different versions of the search code, and their random-number state entering final training is not matched, so initialization and batch order differ.
  • Short-horizon bias is a plausible explanation consistent with the evidence, not something these runs establish on their own.

The follow-up that would settle it: train both configurations for the full three epochs across several seeds on an identical split, and report mean and spread. To test the short-horizon explanation directly, score candidates at several budgets — 300 batches, one epoch, three epochs — and measure how well each budget's ranking predicts final accuracy.

Reproduce

The Colab notebook runs everything end to end on a free GPU. Locally:

git clone https://github.com/jeorgexyz/BERT-BoSA.git
cd BERT-BoSA
python -m venv .venv && .venv\Scripts\activate
pip install -r requirements.txt

python train.py --sa-iterations 15 --sa-train-batches 300 --epochs 3 --seed 42
python eval.py --checkpoint model.pt
python plot_sa.py --log sa_log.csv --output sa_trace.png

The recorded run used a Colab T4 with Python 3.13. Full method and analysis are in the report (markdown).
